iADB requires an Android device to review its remote features. The app has no account, cloud service, analytics, or developer-operated server. It communicates with the Android device over the local network after Android authorizes Wireless debugging.

Test setup:
1. Use an Android device running Android 11 or later.
2. Connect the iPhone or iPad and the Android device to the same local Wi-Fi network.
3. On Android, enable Developer options, open Wireless debugging, and choose Pair device with pairing code. Manufacturers may use different Settings labels.
4. In iADB, allow Local Network access, tap Connect a Device on the welcome screen, and choose Pair Device. Enter the Android address, pairing port, and six-digit pairing code if discovery has not filled them in.
5. Use the pairing port shown in the Android pairing dialog. This port is different from the Wireless debugging connection port shown on the main Wireless debugging screen.
6. After pairing, iADB connects automatically if the discovered Bonjour service is still available. Otherwise, iADB opens a connection form. Enter the IP address and regular Wireless debugging port from Android's main Wireless debugging screen, then tap Connect.

The Device workspace shows device health and connection controls. Files, Apps, Console › Command Runner, Console › Logcat, and Screens use the selected device shown in Device Context. Activity Center tracks transfers, APK installs, captures, and exports.

iADB keeps local screenshot files and the current workspace context after a disconnect. Reconnect requires a user action. iADB does not run a queued command or destructive action after reconnect. Large transfers and installs require iADB to remain in the foreground because iOS may suspend network work after the reviewer leaves the app.

The deterministic screenshot fixture is guarded by DEBUG compilation and is absent from the submitted Release build.
